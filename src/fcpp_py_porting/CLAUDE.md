# CLAUDE.md — fcpp_py (Python bindings)

## What this project is

Python 3.x bindings for the `fcpp` C++14 aggregate computing framework.
Bridge: **ctypes + C ABI** — same pattern as `../expr_eval_py/`.

```python
from fcpp_py import Vec2, Vec3, version
v = Vec2(3.0, 4.0)
v.norm()                   # → 5.0
v.unit()                   # → Vec2(0.6, 0.8)
v + Vec2(1.0, 0.0)         # → Vec2(4.0, 4.0)
v.dot(Vec2(1.0, 0.0))      # → 3.0
version()                  # → "1.0.0"
```

## Environment

### Windows 11 (MSYS2 UCRT64)
- Python: auto-detected via `command -v python3` (falls back to `command -v python`); tested with 3.14.0 (MSVC build, 64-bit)
- Compiler: GCC 15.2.0 (MSYS2 UCRT64) — **not MSVC**
- Make: `mingw32-make`
- pytest: `pip install pytest`
- fcpp source: `fcpp_clone_GITIGNORE_ME/` (git-ignored)

### Linux (Mint / Ubuntu)
- Python: system `python3` (any ≥ 3.8)
- Compiler: GCC ≥ 15 required for `-std=c++26`
- Make: `make`
- pytest: `pip3 install pytest`

**Why ctypes not pybind11/nanobind:** Python 3.14 = MSVC build; GCC = MSYS2 → C++ ABI mismatch → pybind11/nanobind crash. C ABI (`extern "C"`) is compiler-neutral. Full rationale in `explanation.md §1`.

## Build

```bash
# Windows (MSYS2 bash) — from src/fcpp_py_porting/:
mingw32-make all    # builds fcpp_py/_fcpp_core.dll + copies libwinpthread-1.dll
mingw32-make test   # build + run pytest
mingw32-make clean  # remove DLL + copied runtime

# Linux — from src/fcpp_py_porting/:
make all            # builds fcpp_py/_fcpp_core.so
make test           # build + run pytest
make clean          # remove .so
```

**What `all` does:**
1. Compiles `src/bridge.cpp` incrementally into `build/bridge.o` (`-MMD -MP` auto-generates `.d` dep file).
2. Links to `fcpp_py/_fcpp_core.dll` (Windows) / `_fcpp_core.so` (Linux).
3. **Windows only:** Copies `libwinpthread-1.dll` from `$MSYSTEM_PREFIX/bin/` (default `/ucrt64`) into `fcpp_py/` — proper Make dependency target; runs only when source newer than destination.
4. fcpp is header-only templates; no fcpp `.cpp` files need compiling.

`__init__.py` calls `os.add_dll_directory(package_dir)` before `ctypes.CDLL` — Windows finds `libwinpthread-1.dll` next to main DLL without MSYS2 on PATH.

## C bridge API (bridge.cpp)

```c
const char* fcpp_py_version(void);

// Vec2: arrays of 2 doubles
double  fcpp_vec2_norm    (const double* v);
double  fcpp_vec2_distance(const double* a, const double* b);
double  fcpp_vec2_dot     (const double* a, const double* b);
void    fcpp_vec2_add (const double* a, const double* b, double* out);
void    fcpp_vec2_sub (const double* a, const double* b, double* out);
void    fcpp_vec2_mul (const double* a, double s,        double* out);
void    fcpp_vec2_div (const double* a, double s,        double* out);
void    fcpp_vec2_neg (const double* a,                  double* out);
void    fcpp_vec2_unit(const double* a,                  double* out);
int32_t fcpp_vec2_eq  (const double* a, const double* b);  // 1=equal, 0=not

// Vec3: same pattern with 3-element arrays
// fcpp_vec3_{norm,distance,dot,add,sub,mul,div,neg,unit,eq}
```

Bridge uses `memcpy` between `const double*` and `fcpp::vec<N>.data`.
`static_assert(std::is_same_v<fcpp::real_t, double>)` guards against fcpp config changes.

## Python API

```python
version() -> str

class Vec2:
    Vec2(x: float = 0.0, y: float = 0.0)
    x: float          # property (read)
    y: float          # property (read)
    def __getitem__(i: int) -> float
    def __setitem__(i: int, v: float) -> None
    def norm() -> float
    def unit() -> Vec2
    def dot(other: Vec2) -> float
    def distance(other: Vec2) -> float
    # operators: +, -, * (scalar), / (scalar), - (unary), ==, !=
    # protocol:  __iter__, __len__, __repr__

class Vec3:          # same + z property
    Vec3(x: float = 0.0, y: float = 0.0, z: float = 0.0)
    z: float
    # all Vec2 ops present
```

## What must never change

- `fcpp_clone_GITIGNORE_ME/` — read-only; not owned by this project.
- `extern "C"` on all bridge functions — removing breaks ctypes.
- Array convention: Vec2 = 2 doubles, Vec3 = 3 doubles — Python and C must agree.
- `static_assert(std::is_same_v<fcpp::real_t, double>)` in bridge — catches fcpp config changes.
