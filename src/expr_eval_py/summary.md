# Summary — `expr_eval_py`: Python bindings for the ExprEval C++26 library

## What was built

A Python package (`expr_eval_py`) that exposes the C++26 boolean expression
evaluator to Python 3.x via a thin C ABI bridge and `ctypes`.

```python
from expr_eval_py import evaluate

result = evaluate("v1 > 10 && v2 == true", {"v1": "15.5", "v2": "true"})
# → True
```

## How to build and use

```bash
# ── Windows (MSYS2 bash) ──────────────────────────────────────────────────────
# 1. Build the DLL
mingw32-make all

# 2. Run the tests
mingw32-make test
# or directly:
python -m pytest tests/ -v

# 3. Use from Python
python -c "
from expr_eval_py import evaluate
print(evaluate('v > 10 && flag', {'v': '15', 'flag': 'true'}))
"

# ── Linux (bash) ──────────────────────────────────────────────────────────────
# 1. Build the .so
make all

# 2. Run the tests
make test
# or directly:
python3 -m pytest tests/ -v

# 3. Use from Python
python3 -c "
from expr_eval_py import evaluate
print(evaluate('v > 10 && flag', {'v': '15', 'flag': 'true'}))
"
```

## Public Python API

```python
from expr_eval_py import evaluate, version, ParseError, EvaluationError

# evaluate(expression, variables=None, *, verbose=False) -> bool
evaluate("true")                                    # → True
evaluate("v == 1", {"v": "1"})                     # → True
evaluate("v1 > 10 && v2 == true",
         {"v1": "15.55", "v2": "true"})            # → True
evaluate("v > 10", {"v": "5"}, verbose=True)       # prints AST, returns False

version()                                           # → "1.0.0"
```

### Supported operators (unchanged from C++ library)

| Category | Operators |
|---|---|
| Equality | `==`, `!=` |
| Numeric comparison | `<`, `<=`, `>`, `>=` |
| Logical | `&&`, `\|\|`, `!` |
| Unary negation | `-` |
| Grouping | `( )` |

### Variable values

All variables are passed as strings.  The C++ library parses each string as:
1. `"true"` or `"false"` → boolean
2. Any valid number (`"3.14"`, `"-10"`, `"0"`) → float
3. Anything else → `EvaluationError`

### Exceptions

| Python exception | Inherits from | When raised |
|---|---|---|
| `ParseError` | `ValueError` | Expression is syntactically malformed |
| `EvaluationError` | `RuntimeError` | Type mismatch, unknown variable, non-boolean root |

## Architecture — the bridge

```
Python caller
    │
    │  evaluate("v > 1", {"v": "5"})
    ▼
expr_eval_py/__init__.py          (pure Python — ctypes)
    │  converts str/dict → C types
    │  calls expr_eval_evaluate(...)
    ▼
bridge/bridge.cpp  ──compiled──►  _expr_eval_core.dll
    │  catches ALL C++ exceptions
    │  converts to int32 error code + char* message
    │  suppresses std::cout (unless verbose=1)
    ▼
ExprEval::evaluate(expression, variables)   (C++26 library)
    │  parses → optimizes → evaluates → returns bool
    ▼
back up through the same chain → Python bool
```

The C++ exception types never cross the language boundary.  Only C-compatible
types (`int32_t`, `char*`) are passed across.  This makes the DLL loadable
from any Python build regardless of compiler.

## Known limitation

`verbose=True` is not thread-safe: it redirects `std::cout` globally.
In a multi-threaded Python program, concurrent calls with `verbose=True` may
interleave output.  `verbose=False` (the default) redirects to an
`ostringstream` but shares the same global lock concern — however since
output is discarded, interleaving is invisible and harmless.
